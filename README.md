# AI Image Detector

A research prototype that estimates whether an image was **made by a camera or generated by AI**, shows which regions
influenced the model, and states how far the answer can be trusted. It is **not forensic proof** and must not be the sole
basis for any decision about a person or an image.

Every number below is measured on data the model did not train on; `docs/EXPERIMENTS.md` explains how.

## What it does
* **Prediction** - a *calibrated* probability that the image is AI-generated plus a verdict: *likely AI*, *likely real*, or
  *inconclusive* (an abstain band set on a held-out calibration split for about 90 % class-balanced precision).
* **Visual evidence** - Grad-CAM of the model's own output, stitched over the 256 px regions it analysed. It shows where the
  *model* looked, not where an image was edited. On 80 validation images, removing the highlighted regions lowered the model's
  score more than removing random regions in **76 %** of cases (chance is about 25 %).
* **Forensic observations** - file format, estimated JPEG quality, EXIF count, ELA and spectrum views. These are generic
  checks the detector does **not** use and carry no decision threshold.
* **Reliability** - measured benchmark, per-generator detection rates, per-source false-alarm rates, robustness table.

## Measured results (model `general_native_b`, EfficientNet-B0, native-resolution tiles)
Independent benchmark **CompEval-v2**: 2,315 AI images from 8 generators plus 1,469 real images (LAION, ImageNet, COCO,
RAISE, FFHQ). Whole generator *families* (Midjourney, FLUX, Imagen, Stable Cascade, Kandinsky 2.2) and disjoint real-image
files were withheld from training, calibration and model selection.

| metric (clean images) | value (95 % bootstrap CI) |
|---|---|
| ROC-AUC | **0.909** (0.900-0.918) |
| AI images caught (recall at P(AI) >= 50 %) | 72.5 % |
| Real images kept real (specificity) | 88.8 % |
| AI precision / F1 | 91.1 % / 0.807 |
| Balanced accuracy | 80.7 % |
| Calibration error (ECE) / Brier | 0.022 / 0.141 |

Detection rate by generator (clean): Imagen 3 **50 %**, Midjourney v6.1 **53 %**, Midjourney v5.2 **56 %**, FLUX-schnell 73 %,
Midjourney v6 (community) 74 %, FLUX-dev 79 %, Kandinsky 2.2 95 %, Stable Cascade 98 %.
Real images kept real, by source: FFHQ 100 %, RAISE 97 %, COCO 91 %, LAION 88 %, **ImageNet 79 %**.

Robustness (same images, degraded; ROC-AUC): JPEG-75 0.938, JPEG-50 0.954, social-media style (<=1080 px + JPEG-70) 0.941,
grayscale 0.926, blur 0.881, half-size 0.842, **quarter-size 0.763**. AUC is higher after JPEG recompression than on clean
images, which suggests a residual format difference between the sampled fake and real sets that recompression partly hides;
treat the clean row as the primary figure.

Not measured and not claimed: generators outside the benchmark (e.g. DALL-E, Firefly, Ideogram), edited or inpainted real
photos, screenshots, illustrations, video, and face-swap deepfakes. Per-generator samples are a few hundred images, so
per-generator rates are uncertain by roughly +-6 points.

### Known failure cases
* Imagen 3 and Midjourney are caught only about half the time - not reliable for them.
* About 1 in 5 ImageNet-style real photos is flagged as AI.
* Quarter-size/thumbnail images lose most of the signal; images under 256 px are flagged as unreliable.
* In the bundled `test_images/`, `face_real.jpg` scores 85 % AI (a false alarm) and `face_fake.jpg` is *inconclusive*.
  `Fakers.jpg`, `fake_20.png` and `real_20.png` have no verified labels and support no claim.
* The earlier face-only models (`candidate_A_mild.pt`, `best_finetuned.pt`) are kept for comparison and rollback only.

## Setup
```
python -m venv .venv
.venv\Scripts\activate                       # Windows; use source .venv/bin/activate elsewhere
pip install -r requirements.txt
python -m pytest tests -q                    # 19 tests, a few minutes
streamlit run app.py                         # web UI
python predict.py path\to\image.jpg [--json] # CLI, same code path as the UI
```
The default model comes from `models/active_model.json`. Override with `--model file.pt` or `DETECTOR_MODEL=file.pt`;
`DETECTOR_BACKEND=legacy` restores the original Keras Xception path (needs TensorFlow).

## How it works
Images are split into up to nine 256x256 native-resolution tiles (no resizing, so resolution traces are preserved), each
scored by EfficientNet-B0 with horizontal-flip TTA. Tile logits are averaged and divided by a temperature fitted on a
held-out calibration split (T = 1.62). A decision band turns the probability into likely-AI / likely-real / inconclusive.

Files: `detector.py` (shared inference), `general.py` (tiling), `app.py`, `predict.py`, `explain.py`, `train_general.py`,
data builders `cf_build.py` / `oi_build.py` / `ce_fetch.py` / `ce_build.py`, evaluation `eval_general.py` +
`eval_metrics.py`, and `make_model_card.py` (writes the numbers the UI shows).

## Limitations
The model learned statistical differences between the sampled generators and sampled real-photo sources. Both are samples,
and their formats and sizes differ in ways only partly controlled. Performance on a new generator, camera pipeline or heavy
social-media re-processing can be much worse than reported. FFHQ-style portraits may share identities between training and
benchmark data; identity leakage could not be ruled out. Attention maps do not prove manipulation.
